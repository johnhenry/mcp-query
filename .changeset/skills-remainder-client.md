Skills over MCP, the rest of the client side. `client.readSkillDirectory(uri, server)` (also on `scope()`) reads a skill directory over `resources/directory/read` when the server advertises `directoryRead` (a clear `MCPError` otherwise), cached under the server's ttl and run through the interceptor chain as a `skill` operation. `CallContext.meta` now travels as `_meta` on `skills/list`, `skills/get`, directory reads and the `resources/read` behind `readSkillFile`: the SDK's `SkillsClient` takes no `_meta`, so it is given a view of the SDK `Client` that injects it. New opt-in `MCPClientConfig.skillApproval` (default off, needs `interactions`) routes the first read of a skill through the `InteractionBroker` (`gate("confirm", ...)`, payload `{ action: "skill-load", ... }`), bound to the manifest's digest set so a changed manifest asks again; a denial is an `MCPError` and nothing is cached. Verified skill files also use the configured `cacheStore` (digest-keyed, re-hashed against the manifest on read-back, `cacheScope` respected). Adds `skillFileCacheKey`, the `SkillDirectory` / `SkillApprovalConfig` types, and `MockMCPServer` `skillsDirectoryRead` + `skillMetaLog`.
