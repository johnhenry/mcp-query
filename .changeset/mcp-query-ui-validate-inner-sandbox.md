BREAKING: the deprecated `mountIframe({ innerSandbox })` string is now validated exactly like `sandbox.inner`. Before, it was passed through to the inner app frame unchecked, so a host could set tokens the MCP Apps sandbox rules forbid (for example `allow-same-origin`, which lets the app lift its own sandbox) without any opt-in. Now `mountIframe` throws, before touching the DOM, when `innerSandbox` contains `allow-same-origin` (never permitted, no option lifts it), an unknown token (a typo the browser used to ignore), or any token beyond `allow-scripts` without `sandbox: { unsafeLoosen: true }`; the error names the token and the opt-in. Passing both `innerSandbox` and `sandbox.inner` is now an error (before, `sandbox.inner` silently won). `resolveSandbox(opts, legacyInner)` behaves the same way. `innerSandbox` is marked `@deprecated`. Migrate by moving the value to `sandbox.inner` (add `sandbox: { unsafeLoosen: true }` only if you need more than `allow-scripts`): `innerSandbox: "allow-scripts allow-forms"` becomes `sandbox: { inner: "allow-scripts allow-forms", unsafeLoosen: true }`. A host that only used `innerSandbox: "allow-scripts"` (or a subset, or nothing) is unaffected. See "Migrating to 3.0" in the README. The peer floor `@johnhenry/mcp-query >=0.5.0` is unchanged: it was verified against the published 0.5.0 and 0.6.0 (and 0.7.0) with `scripts/peer-floor-smoke.mjs`, which installs each from npm next to a packed tarball and runs a real host smoke (app session, tool call, resource read, opt-in `resources/list` falling back when `client.discover` is absent on 0.5.0).
